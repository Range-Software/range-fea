## 1. Теоретичні основи

### 1.1 Первинне невідоме - температурне поле

Основним невідомим є **температура** `T` у кожному вузлі, у кельвінах. Кожен вузол має один ступінь свободи, тому сітка з вузлами `N` дає систему рівнянь `N`. Тепловий потік відновлюється з поля температури після розчину.

Температура є скаляром, що робить теплову модель помітно дешевшою, ніж структурна модель тієї самої сітки: одне невідоме на вузол замість трьох, і матриця з дев’ятою частиною елементів.

Температура за замовчуванням вузла, якого не торкаються жодні умови та попередні результати, становить `293.15 K`.

### 1.2 Керуюче рівняння

Розв’язувач реалізує **лінійну теплопровідність** із конвективними межами. Енергетичний баланс тіла з провідністю `k`, густиною `rho` і питомою теплоємністю `c`

```
rho * c * dT/dt = div( k * grad(T) ) + q
```

і з вимкненим вирішувачем часу перехідний термін випадає, залишаючи рівновагу в стаціонарному стані

```
div( k * grad(T) ) + q = 0
```

Тепло залишає поверхню шляхом конвекції відповідно до закону охолодження Ньютона,

```
qs = h * ( T - Tf )
```

| Символ | Значення | Одиниці | Джерело |
|---|---|---|---|
| `T` | температура | `K` | вирішено для |
| `q` | щільність джерела тепла | `W/m^3` | Тепловий стан, джоулева теплота, випромінювання |
| `k` | теплопровідність | `W/(m*K)` | матеріальне майно |
| `c` | теплоємність | `J/(kg*K)` | матеріальне майно |
| `rho` | щільність | `kg/m^3` | матеріальне майно |
| `h` | |коефіцієнт конвекції | `W/(m^2*K)` | умови конвекції див. 1.5 |
| `Tf` | температура рідини | `K` | умова конвекції |
| `Q` | тепловий потік | `W/m^2` | відновлено, див. 1.9 |

Терміну адвекції немає. Задача теплопередачі переміщує енергію шляхом провідності всередині тіла та конвекції через його кордон; він не переміщує енергію з текучим середовищем. Для цього використовуйте *Теплообмін у рідинах*.

**Необхідні властивості матеріалу.** Теплова задача потребує **чотирьох** із них:

| Власність | Одиниці | Використовується для |
|---|---|---|
| Теплопровідність | `W/(m*K)` | матриця провідності |
| Теплоємність | `J/(kg*K)` | матриця пропускної здатності, тільки перехідний |
| Щільність | `kg/m^3` | матриця пропускної здатності, тільки перехідний |
| Коефіцієнт випромінювання | `-` | тільки радіаційний теплообмін |

Сутність, у матеріалі якої відсутній будь-який із чотирьох параметрів, **не розкрита**, навіть для чистого стаціонарного аналізу провідності, який ніколи не розглядає щільність або коефіцієнт випромінювання. Програма перевірки налаштувань попереджає про це перед початком запуску. Єдиним винятком є ​​сутність, яка має теплову граничну умову: ця сутність включена в систему незалежно від того, що говорить її матеріал, і тоді її провідність і ємність просто дорівнюють нулю.

Кожна властивість є таблицею температур. Значення, яке використовується для елемента, зчитується з таблиці за **температурою елемента попереднього циклу**, тому залежна від температури провідність запізнюється на одну ітерацію. Розділ 1.6 пояснює, як це зблизити.

### 1.3 Дискретизація скінченних елементів

Слабка форма енергетичного балансу дає для кожного елемента

```
K = INT( B^T * k * B )  +  INT( N^T * h * N )      conduction + convection
M = INT( rho * c * N^T * N )                       capacity matrix
f = INT( N^T * q )  +  h * Tf * A / n              sources + convection
```

, де `B` побудовано з похідних функції форми, а `N` є самими функціями форми. Кожна матриця елемента є `n x n` для елемента з вузлами `n` - один рядок на вузол, а не три.

Терміни конвекції зібрані на **лише елементах поверхні** і лише там, де призначено граничну умову конвекції. Жорсткість конвекції має постійну форму `INT( N^T * h * N )`, тоді як конвекційне навантаження рівномірно зосереджено на вузлах елемента. Обидва є досить узгодженими на розумній сітці, і різниця зникає, коли сітка уточнюється.

**Елементні міри.** Як і скрізь у Range FEA, нижчим вимірам надається геометрична міра, щоб вони могли представляти реальні тіла:

| Суб'єкт | Виміряти | Де встановлено |
|---|---|---|
| Обсяг | 1 | - |
| Поверхня | товщина поверхні | геометричні властивості сутності |
| Лінія | площа перетину лінії | геометричні властивості сутності |
| Точка | точковий обсяг | геометричні властивості сутності |

**Поверхня** проводить тепло у власній площині через поперечний переріз, що дорівнює її товщині, і накопичує енергію пропорційно цій товщині. Немає градієнта температури по товщині: поверхневий елемент має товщину в один вузол, тому за своєю конструкцією він ізотермічний по товщині. Таким чином, поверхня **нульової товщини** нічого не проводить і нічого не зберігає, але все ще несе конвекцію – це саме те, що потрібно для граничної грані сітчастого об’єму, де грань існує лише для підтримки умов конвекції.

**Лінія** проходить у власному напрямку через свою поперечну площу. **Точка** не має напрямку, щоб проводити, тому вона взагалі не сприяє провідності: вона несе лише ємність, пропорційну її об’єму точки, і джерело тепла. Точка — це зосереджена теплова маса, а не провідник.

Матриця ємності збирається лише тоді, коли це необхідно, тобто для аналізу перехідних процесів.

### 1.4 Джерела та граничні умови

| Гранична умова | Тип | Застосовується до | Компоненти |
|---|---|---|---|
| Температура | явний (Діріхле) | точка, лінія, поверхня, об'єм | Температура `[K]` |
| Тепло | природний, джерело | точка, лінія, поверхня, об'єм | Нагрійте `[W]`, див. нижче |
| Проста конвекція | природний (Робін) | поверхні | Коефіцієнт конвекції `[W/(m^2*K)]`, Температура рідини `[K]` |
| Примусова конвекція | природний, кореляційний | поверхні | Густина, Динамічна в'язкість, Температура рідини, Теплоємність, Гідравлічний діаметр, Теплопровідність, Швидкість |
| Природна конвекція | природний, кореляційний | поверхні | Густина, Динамічна в'язкість, Температура рідини, Теплоємність, Гідравлічний діаметр, Теплопровідність, Коефіцієнт теплового розширення |
| Теплова швидкість (одиниця площі) | природний, джерело | поверхні | Теплота на одиницю площі `[W/m^2]` |
| Теплова швидкість (одиниця об'єму) | природний, джерело | обсяг | Теплота одиниці об’єму `[W/m^3]` |

**Температура** є єдиною явною умовою задачі тепла. Кожен вузол сутності, якій він призначений, видаляється із системи рівнянь і зберігається на заданому значенні; його внесок переноситься в праву частину сусідніх рівнянь. Для стаціонарної моделі потрібна принаймні одна з них або принаймні одна конвекційна поверхня - див. 1.7.

Якщо сутності перекриваються, **нижньовимірна сутність виграє**: температура, встановлена ​​на поверхні, перекриває температуру, встановлену в об’ємі за нею в спільних вузлах, лінія перекриває поверхню, а точка перекриває все. На відміну від обмежень переміщення структурного розв’язувача, температури не поєднуються – існує лише один ступінь свободи для кожного вузла, тому остання зчитана умова просто переважає.

**Тепло** є джерелом тепла, а його значенням є **загальна потужність у `W`**, що постачається в об’єкт, якому він призначений, незалежно від розміру цього об’єкта. Розв’язувачу потрібна джерельна щільність, тому підсумок розподіляється на міру об’єкта перед складанням:

| Суб'єкт | Щільність розв'язувач застосовує |
|---|---|
| Обсяг | значення/обсяг сутності, `W/m^3` |
| Поверхня | значення/площа сутності, `W/m^2` |
| Лінія | значення/довжина сутності, `W/m` |
| Точка | значення / кількість точкових елементів, `W` кожен |

Таким чином, передана потужність точно відповідає введеному числу - вона не змінюється з розміром сутності, з уточненням сітки або з масштабом моделі. Лише елементи, які розв’язувач може обчислити, мають частку, тому об’єкт без матеріальних властивостей пропускається, а натомість повідомляється про його стан. Поверхневе джерело тепла не масштабується товщиною поверхні.

**Швидкість тепла (одиниця площі)** і **Швидкість теплоти (одиниця об’єму)** передбачають той самий вихідний термін як щільність замість загальної: `W/m^2` за площею об’єкта поверхні та `W/m^3` за об’ємом об’єкта об’єму. Потягніться до них, коли джерелом є природна щільність – обігрівач, розрахований на квадратний метр – і до *Теплота*, коли це природно загальна кількість, наприклад, елемент із відомою потужністю. Усі вони складаються в один об’єкт, який містить більше одного, і всі вони приймають таблицю в залежності від часу, тому нагрівач можна вмикати та вимикати під час перехідного циклу.

Умови **конвекції** застосовуються до поверхонь і додають як термін жорсткості, так і навантаження, тому вони діють як граничні умови Робена, а не як фіксований потік: підвищення температури стінки збільшує втрату тепла стіною. Усі три смаки закінчуються як одна пара `(h, Tf)`; вони відрізняються лише тим, звідки походить `h`:

- **Проста конвекція** бере `h` і `Tf` безпосередньо з двох введених значень. Використовуйте його щоразу, коли коефіцієнт конвекції відомий із посібника, вимірювання чи попереднього розрахунку. Це єдиний із трьох, який повністю під вашим контролем.
- **Примусова конвекція** має два режими. На стіні між сітчастим твердим тілом і сітчастою рідиною, як тільки завдання *Передача тепла в рідинах* дає результат, воно об’єднує два розв’язки напряму – кореляція не задіяна, оскільки розв’язаний потік уже несе конвекцію. Тепловий розв’язувач рідини передає для кожного елемента стіни пару `(h, Tf)`, яка відтворює тепловий потік, який його власний розчин приймає через стіну; див. *Спряжена теплопередача* в 1.6. У будь-якому іншому місці — поверхня, що межує з рідиною без сітки, або перший прохід пов’язаного циклу перед виконанням завдання нагрівання рідини — `h` обчислюється на основі кореляції зовнішнього потоку вздовж плоскої пластини з використанням властивостей рідини, гідравлічного діаметра, *Температури рідини* та *Швидкості*, які ви вводите. У журналі вказано, який із двох використовується.
- **Природна конвекція** обчислює `h` на основі кореляції для горизонтальних пластин, використовуючи властивості рідини, гідравлічний діаметр і різницю температур між стінкою та рідиною.

Якщо одній поверхні призначено кілька умов конвекції, вони не сумуються: простий зчитується спочатку, примусовий перезаписує його, а природний перезаписує обидва.

### 1.5 Кореляції конвекції

Обидві обчислені форми будують звичайні безрозмірні групи з властивостей рідини, введених із граничною умовою, з гідравлічним діаметром `d` як характерною довжиною:

```
Pr = c * mu / k                                        Prandtl
Re = rho * v * d / mu                                  Reynolds
Gr = | rho^2 * g * beta * (Ts - Tf) * d^3 / mu^2 |     Grashof,  g = 9.81
Ra = Gr * Pr                                           Rayleigh
```

і перетворити число Нуссельта в коефіцієнт конвекції як

```
h = Nu * k / d
```

| Форма | Кореляція | Число Нуссельта |
|---|---|---|
| Примусовий | зовнішній потік, плоска пластина | `Nu = 0.036 * Re^(4/5) * Pr^(1/3)` |
| Природний | горизонтальна пластина, `Ra < 2e7` | `Nu = 0.54 * Ra^(1/4)` |
| Природний | горизонтальна пластина, `Ra >= 2e7` | `Nu = 0.14 * Ra^(1/3)` |

`k`, `c`, `rho`, `mu` і `beta` у цих виразах є властивостями **рідин**, введеними з граничною умовою, а не властивостями матеріалу твердого тіла.

Обидві умови створено з урахуванням властивостей **сухого повітря при 20 градусах за Цельсієм і 101,325 кПа**, тому рідина описана для вас, і залишилося ввести лише потік і геометрію:

| Компонент | За замовчуванням |
|---|---|
| Щільність | `1.2041 kg/m^3` |
| Динамічна в'язкість | `1.8205e-5 kg/(m*s)` |
| Теплоємність | `1005 J/(kg*K)` |
| Теплопровідність | `0.02514 W/(m*K)` |
| Коефіцієнт теплового розширення | `3.4112e-3 1/K`, значення ідеального газу `1/T` |
| Температура рідини | `293.15 K` |
| Гідравлічний діаметр | `1 m` |

Замініть їх будь-якою іншою рідиною - це властивості рідини, а не матеріалу стінки. Таким чином, *природна конвекція* готова до виконання завдань; *Примусова конвекція* все ще потребує **швидкості**, яку не може вгадати жодне значення за замовчуванням, якщо тільки поверхня не межує із сітчастою рідиною, де жодне з цих значень не зчитується.

Кожна з цих груп ділиться на `mu`, `k` або `d`, а `Re` і `Pr` падають до нуля, якщо `rho`, `c` або `v` діляться, що залишає `h = 0` і поверхню, яка ніколи не охолоджується. Таким чином, нульове значення розглядається як помилка, а не замовчується: розв’язувач зупиняється та називає компонент і сутність, наприклад

```
Value of 'Velocity' configured in 'Forced convection' boundary condition on
entity 'Surface' is zero - the convection correlation can not be evaluated.
```

Швидкість, яку обчислює розв’язувач потоку, ніколи не вводиться в кореляцію. Нековзаюча стінка утримує рідину в стані спокою, тому швидкість поруч із нею дорівнює нулю, і для кореляції знадобляться швидкість вільного потоку та об’ємна температура, які загальний тривимірний потік не визначає. Натомість стінка, що межує із сітчастою рідиною, з’єднана з розчином рідини.

Варто мати на увазі три наслідки:

- кореляція **фіксована**. Розв’язувач не дивиться на орієнтацію поверхні, на те, чи є потік внутрішнім чи зовнішнім, чи є прикордонний шар ламінарним чи турбулентним. Все входить через гідравлічний діаметр, який є характерною довжиною кореляції - це ваша єдина ручка для геометрії.
– Гідравлічний діаметр, рівний нулю, дасть `h = 0`, тобто ізольовану стіну, тому розв’язувач зупиняється, а не приймає це.
- Природна конвекція залежить від **температури стінки**, яка береться з температури елемента **попереднього** рішення. Під час першого запуску аналізу стаціонарного стану це початкова температура, тому коефіцієнт оцінюється за неправильної різниці температур. Об’єднайте завдання в групу розв’язування задач з кількома ітераціями, щоб зблизити його, або використовуйте *Просту конвекцію* з коефіцієнтом, який ви обчислили самостійно. Різниця температур, що зникає, дає `Nu = 1`.

### 1.6 Середовище, початкові умови та умови сполучення

#### Умови середовища

| Стан середовища | Компоненти | Ефект |
|---|---|---|
| Температура | Температура `[K]` | фонова температура об'єкта, тільки перший запуск |

#### Початкові умови

| Початковий стан | Ефект |
|---|---|
| Температура | початкове температурне поле, застосоване при першому запуску |

Умови середовища, початкові умови та граничні умови зчитуються в такому порядку, і кожна перезаписує попередню, тому **гранична умова перемагає над початковою умовою, яка перемагає над умовою середовища**. Середовище та початкові значення зчитуються під час **лише першого запуску**; після цього поле йде від попереднього результату.

#### З'єднання з іншими розв'язниками

Тепловирішувач як споживає, так і виробляє результати, спільні з рештою потоку завдань.

| Напрям | Змінна | Ефект |
|---|---|---|
| Радіаційний теплообмін -> тепло | Тепло - радіаційна частина | додано до вихідного терміну елементів **поверхні** |
| Електростатика -> тепло | Джоулева теплота | додається до вихідного терміну кожного елемента |
| Стрес -> тепло | Водотоннажність | сітка деформується для розчинення тепла і відновлюється після |
| Тепло -> стрес | Температура | керує терміном теплового розширення структурного вирішувача |
| Тепло -> будь-який розв'язник | Температура | вибирає рядок кожної таблиці матеріалів, залежних від температури |
| Тепло рідини -> тепло | Стіна `(h, Tf)` | керує стінками *примусової конвекції*, що межують із сітчастою рідиною |
| Тепло -> тепло рідини | Температура твердого | тримає ж стінки при температурі твердого тіла в рідині розв'яжіть |

**Радіаційний теплообмін** є окремим типом задач зі своїм розв’язувачем. Це вимагає завдання *Передача тепла*, розв’язує систему випромінювання корпусу на ділянках поверхні, використовуючи коефіцієнти огляду та випромінювальну здатність матеріалу, і повертає результат як поверхневе джерело тепла. Додайте обидва завдання в одну групу розв’язування задач і дозвольте групі повторювати: випромінювальний розв’язувач повідомляє про збіжність і завершує групу, коли її нагрівання перестає змінюватися.

**Джоулеве тепло** надходить таким же шляхом із завдання *Електростатики*, розміщеного перед завданням нагрівання, тому резистивне нагрівання не потребує подальшого налаштування.

Якщо він не пов’язаний з рідиною, розв’язувач тепла повідомляє про себе як про безумовну конвергенцію, тому група завдань, яка містить лише завдання нагрівання, завжди зупиняється після однієї ітерації. Ітерація доцільна, коли щось, від чого залежить розв’язання тепла, саме по собі має затримку – радіаційне тепло, природний коефіцієнт конвекції або сильно залежна від температури провідність.

#### Сполучений теплообмін

Теплорозв’язувач вирішує **лише тверді тіла**. Об’єм, матеріалом якого є рідина – газ чи рідина, або матеріал у невизначеному стані, що має динамічну в’язкість, яка охоплює кожну рідину бази даних матеріалів – ніколи не є частиною теплового розчину, незалежно від властивостей чи умов, які він несе. Так само є точка, лінія або поверхнева сутність, що лежить всередині рідини, наприклад впускний отвір; умова, яку зчитує лише тепловимірювач, повідомляється в журналі. Область рідини належить до типу задач *Теплопередача в рідинах*, яка переносить тепло з потоком.

Обидва зустрічаються на стінах із умовою **Примусової конвекції**. З обома завданнями в одній задачній групі завдань — спочатку завданням із теплом рідини — кожен прохід групи виконує наступне:

1. Розв’язувач тепла рідини утримує вузли стінки при температурі, яку востаннє обчислив розв’язувач тепла в твердому тілі (на першому проході, коли такої температури ще немає, стінка ізольована), розв’язує рідину та приймає тепловий потік, що надходить у рідину в кожному вузлі стіни. Цей потік є залишком рівнянь рідини у вузлі, який побачить одне розв’язання обох доменів, тому тонкий тепловий граничний шар не коштує точності.
2. Для кожного елемента стіни він передає пару `(h, Tf)`. `h = k * G` – це провідність першого елемента рідини за стінкою – `k` по висоті елемента над стінкою, для тетраедра – а `Tf` встановлено таким чином, що `q = h * (Tw - Tf)` є потоком кроку 1.
3. Розрахунок тепла застосовує їх до стіни, як це було б за умов *простої конвекції*, розчиняє тверду речовину та повертає температуру її стінки.

Пара `(h, Tf)` є числовим пристроєм, який узгоджує два розв’язки – `h` не є коефіцієнтом теплопередачі в посібнику, і він змінюється разом із сіткою. Те, що збігається, - це температура та потік через стінку, які належать до пов’язаної задачі. Нічого про швидкість рідини біля стіни не потрібно, тому стіна без ковзання, де потік перебуває в стані спокою, передає тепло так, як і має бути.

Температура стінки, що передається рідині, зменшується за допомогою **фактора Ейткена**, обчисленого за останніми двома проходами. Без цього тверда речовина з поганою провідністю поруч із добре розчиненою рідиною може потребувати сотень проходів; з ним група зазвичай осідає жменькою. Обидва розв’язувачі повідомляють про відносну зміну свого температурного поля як свою збіжність, поки вони з’єднані, тому встановіть значення збіжності для групи завдань – `1e-6` є розумним початком – і дайте йому достатньо ітерацій. Нульове значення збіжності запускає їх усі.

### 1.7 Стаціонарний аналіз

Коли розв’язувач часу вимкнено, розв’язувач збирає та вирішує

```
K * T = f
```

`K` є симетричним позитивно визначеним, якщо принаймні одна температура була задана, тому його розв’язують за допомогою методу **сполученого градієнта** з попереднім зумовленням Якобі.

Модель стаціонарного стану з **без температурних граничних умов і без конвекційної поверхні** є тепловим еквівалентом необмеженої структури: енергія може бути влита, але їй нікуди вийти, матриця є сингулярною, а розв’язок не сходиться. Кожна стаціонарна модель потребує принаймні одного шляху до відомої температури.

### 1.8 Аналіз перехідних процесів

Коли розв’язувач часу ввімкнено, розв’язувач марширує

```
M * dT/dt + K * T = f
```

з тета-схемою, де `alpha` — коефіцієнт апроксимації маршу за часом:

```
( M + alpha*dt*K ) * T_n+1 = dt*f + ( M - (1-alpha)*dt*K ) * T_n
```

Налаштування *Наближення* розв’язувача часу вибирає `alpha`:

| Наближення | `alpha` | Підсумковий марш | Стабільність |
|---|---|---|---|
| Зворотна різниця (стабільна) | `1` | `(M + dt*K)*T_n+1 = dt*f + M*T_n`, неявний крок | безумовний |
| Центральна різниця (точно) | `0.5` | Кренк-Ніколсон | безумовний, може коливатися |
| Різниця вперед (швидка) | `0` | `M*T_n+1 = dt*f + (M - dt*K)*T_n`, явний крок | умовний |

**Зворотна різниця** є безпечним за замовчуванням для теплової моделі. Це коштує вирішення матриці за крок, але крок обмежений точністю, яку ви хочете, а не розміром найменшого елемента. **Центральна різниця** має точність другого порядку і є кращим вибором, якщо крок у часі достатньо малий, щоб усунути перехідний процес, хоча він може дзвонити під час різкого ввімкнення. **Різниця вперед** ставить всю матрицю провідності на старий крок часу, що робить кожен крок дешевим, а пробіг крихким.

Пряма гілка є стабільною лише тоді, коли часовий крок залишається приблизно нижче

```
dt < rho * c * h^2 / ( 2 * k )
```

, де `h` — найменший розмір елемента. Оскільки коефіцієнт теплопровідності `k/(rho*c)` металу має порядок `1e-5 m^2/s`, елемент міліметрового розміру вже змушує крок у часі значно менше десятої частки секунди. Для чого завгодно, окрім дуже високої чіткості часу, використовуйте неявний марш.

Нестабільний перехідний процес легко розпізнати: температурне поле коливається від кроку до кроку зі зростаючою амплітудою, часто між фізично неможливими значеннями, а не встановлюється. Лікування - це менший часовий крок або неявний марш.

### 1.9 Похідні результати

Після розв’язання тепловий потік елемента відновлюється з температурного поля як середнє за точками інтегрування

```
Q = -k * grad(T)
```

обчислюється в елементі та повертається в глобальні координати для елементів лінії та поверхні. На поверхні, яка несе конвекцію, конвективний потік

```
Qh = h * ( Tf - T )
```

додається уздовж нормалі до поверхні, тому вектор потоку конвекційної грані вказує шлях фактичного відходу тепла.

Потік є **щільністю** у `W/m^2`, незалежною від розміру елемента, у якому його було обчислено, тому його можна порівнювати між елементами та з обчисленням вручну, і він збігається, коли сітка уточнюється.

Також зберігається **коефіцієнт теплопередачі**. Це коефіцієнт, який розв’язувач фактично використовував для кожного елемента поверхні, і це єдиний спосіб побачити, що створили кореляції *Примусової конвекції* та *Природної конвекції*, а на поверхні природної конвекції він змінюється від елемента до елемента, оскільки залежить від місцевої температури стінки. На стінці, сполученій з рідиною, це провідність першого елемента рідини, яка залежить від сітки - див. *Спряжена теплопередача* у 1.6. Він дорівнює нулю для кожного елемента, який не має умови конвекції.

| Результат | Звернутися до | Значення |
|---|---|---|
| Температура `[K]` | вузол | розв'язане температурне поле |
| Тепловий потік `[W/m^2]` | елемент | вектор кондуктивного потоку плюс конвективна частина на конвекційних поверхнях |
| Коефіцієнт теплопередачі `[W/(m^2*K)]` | елемент | використовуваний коефіцієнт конвекції, дорівнює нулю, якщо конвекції немає |

Після кожного запису журнал розв’язувача друкує статистику всіх трьох і значення в будь-яких точках моніторингу.

### 1.10 Стаціонарний чи перехідний?

| | Стаціонарний | Перехідний |
|---|---|---|
| Вирішує | `K*T = f` | `M*T' + K*T = f` у часі |
| Відповіді | "як гаряче стає в кінці" | "скільки часу потрібно, щоб туди дістатися" |
| Використовує щільність і теплоємність | ні, але вони все одно повинні бути присутніми | так |
| Потрібна задана температура або конвекційна поверхня | так | ні, ємності достатньо |
| Записи | один | один на записаний часовий крок |

**Використовуйте аналіз стаціонарного стану для** остаточного розподілу температури безперервно працюючої частини, визначення розміру радіатора, теплового містка в стіні або температурного поля, яке подає дані для аналізу термічної напруги. Це значення за замовчуванням і охоплює більшість завдань.

**Використовуйте аналіз перехідних процесів для** розігріву та охолодження, робочого циклу, термічного удару, загартування чи будь-чого, де вам потрібна постійна часу деталі.

## 2. Графічний інтерфейс користувача

Усе, що має відношення, міститься в доці **Розв’язувач** (вкладки `Problem`, `Boundary conditions`, `Initial conditions`, `Environment conditions`, `Material`, `Results`), меню **Задача** і **Модель**.

### 2.1 Вибір задачі

`Problem` -> `Problem(s) task flow` (`Ctrl+P`) відкриває діалогове вікно потоку розв’язування задач. Додайте завдання та виберіть **Теплопередача** - «Стаціональна та перехідна теплопередача».

Теплопередача вільно поєднується з будь-якою іншою фізикою, крім *Модального аналізу*. Ланцюжки, про які варто знати:

- *Теплопередача* потім *Аналіз напруги* - теплова напруга;
- *Теплопередача* та *Радіаційна теплопередача* в одній ітераційній групі завдань - провідність плюс випромінювання корпусу;
- *Електростатика* потім *Теплопередача* - резистивне нагрівання.

Щоб виконати ітерацію пов’язаної пари, додайте групу завдань і встановіть її кількість ітерацій; група зупиняється раніше, коли кожне завдання в ній повідомляє про конвергенцію.

### 2.2 Вкладка задачі

**Розв’язування в часі** - показано для теплопередачі, оскільки це тип задачі, що залежить від часу. Залиште його вимкненим для аналізу стабільного стану.

| Поле | Значення |
|---|---|
| Увімкнути | вмикає та вимикає перехідний марш |
| Наближення | тета маршу часу: назад, по центру або вперед, див. 1.8 |
| Час початку | перше значення часу в секундах; ігнорується під час перезапуску вирішувача |
| Час закінчення | `start time + time-step size * number of time-steps`, лише для читання |
| Розмір кроку в часі | `dt` за секунди |
| Кількість часових кроків | скільки кроків обчислити |
| Вихідна частота | записувати файл результатів кожні N кроків; `0` записує лише останній крок |

Задача з нагріванням не має власного вікна групи налаштування. Усе інше призначається сутності на вкладках умов.

### 2.3 Вкладка Матеріал

Вкладка `Material` містить список матеріалів, призначених вибраній сутності. Для передачі тепла потрібні **всі чотири**:

| Власність | Одиниці | Коментар |
|---|---|---|
| Теплопровідність | `W/(m*K)` | `k`, про `50` для конструкційної сталі, `15` для нержавіючої сталі, `200` для алюмінію |
| Теплоємність | `J/(kg*K)` | `c`, про `460` для сталі |
| Щільність | `kg/m^3` | `rho`, про `7850` для сталі |
| Коефіцієнт випромінювання | `-` | використовується тільки при радіаційній теплопередачі, але все одно вимагає |

Сутність, у якій відсутній будь-який із них, не вирішується, і засіб перевірки налаштувань попереджає перед початком запуску. Якщо ви не виконуєте радіаційний теплообмін, коефіцієнта випромінювання `0` достатньо, щоб задовольнити вимогу.

Матеріал також має бути **твердим**. Об’єм, матеріалом якого є газ чи рідина, або не має заданого стану та має динамічну в’язкість, залишається для типу задачі *Теплопередача в рідинах*, навіть якщо він має всі чотири властивості.

Кожна властивість є таблицею температур, тому враховується залежна від температури провідність – оцінена за температурою елемента попереднього циклу, що робить завдання повторним, якщо залежність сильна.

### 2.4 Вкладка Граничні умови

Вкладка розділена на список менеджера доступних граничних умов угорі та редактор для вибраного нижче. Спочатку виберіть сутність у дереві `Model`; потім менеджер пропонує умови, дійсні для цього типу сутності та для вибраної задачі. Позначте один, щоб призначити його, а потім відредагуйте його компоненти в нижньому дереві.

Пропонуються умови розділу 1.4. Примітки щодо їх використання:

- **Температура** - це єдина умова, яка має значення, а не визначає його. Призначте його грані, краю або точці, температура яких вам відома.
- **Тепло** пропонується для кожного типу сутності та бере загальну потужність у `W`; розв’язувач поширює його на сутність для вас. Це умова, якої потрібно досягти, коли ви знаєте потужність того, що генерує тепло.
- **Швидкість тепла (одиниця об’єму)** для об’єму та **Швидкість теплоти (одиниця площі)** для поверхні вказують одне й те саме джерело як щільність для джерела, яке природно розраховане на одиницю об’єму або площі.
- Три умови **конвекції** застосовуються лише до поверхонь. Призначте *Просту конвекцію*, якщо у вас немає конкретної причини дозволити розв’язувачу корелювати коефіцієнт замість вас; це передбачуваний. *Примусова конвекція* на стінці, що межує із сітчастою рідиною, поєднує тверде тіло з теплом розчину рідини та не зчитує жоден із його компонентів; в іншому місці він співвідносить коефіцієнт з них.
- Кожен компонент є таблицею залежно від часу, тому встановленій температурі або джерелу тепла можна надати історію часу для перехідного циклу. Таким чином моделюється робочий цикл або нагрівач із нахилом.

### 2.5 Початкові умови та умови середовища

Вкладка `Initial conditions` пропонує *Температура*, яка встановлює початкове поле перехідного режиму. Призначте його всій моделі та вкажіть температуру, з якої починається частина.

Вкладка `Environment conditions` також пропонує *Температуру* як фонове значення для сутності. Обидва зчитуються лише під час першого запуску, і гранична умова перекриває обидва.

### 2.6 Налаштування вирішувача матриць

`Problem` -> `Setup Problem(s) matrix solver` налаштовує ітераційні розв’язувачі. Розрахунок тепла використовує запис **CG**.

Якщо розв’язання в стаціонарному стані не збігається, звичайною причиною є модель без заданої температури та конвекційної поверхні, а не налаштування вирішувача. Перевірте граничні умови перед збільшенням кількості ітерацій.

### 2.7 Точки моніторингу

`Problem` -> `Define monitoring points` розміщує зонди за заданими координатами та вибирає змінну для запису - *Температура* для задачі з теплом. У перехідному режимі історія відображається за допомогою `Report` -> `Monitoring points`, що є найшвидшим способом прочитати криву розігріву або постійну часу з моделі.

### 2.8 Результати та записи

Вкладка `Results` містить список обчислених змінних і керує 3D-переглядом. Температура — вузловий скаляр, тепловий потік — елементний вектор, а коефіцієнт теплопередачі — елементний скаляр, який дорівнює нулю від конвекційних поверхонь.

Вкладка `Records` дока `Model` містить список записів результатів:

- **стаціонарний аналіз** - один запис;
- **перехідний аналіз** - один запис на записаний часовий крок. Анімація записів відтворює розминку.

`Report` -> `Solver log file` показує повний вихід розв’язувача, включаючи статистику температури, теплового потоку та коефіцієнта теплопередачі після кожного запису.

## 3. Підручник - стаціонарний теплообмін

**Ціль.** Обчисліть розподіл температури бруска, який утримується гарячим з одного кінця й охолоджується навколишнім повітрям, і зчитайте температуру на холодному кінці.

У цьому підручнику передбачається модель сітчастого об’єму – довгий ящик працює добре. Використовуйте `File` -> `New model`, намалюйте прямокутник за допомогою `Geometry` -> `Create element` або імпортуйте геометрію та тетраедралізуйте її; підручник *Побудова куба* охоплює цю тему. Позначте гарячу торцеву поверхню та решта граней як окремі поверхневі сутності, щоб їм можна було призначити умови.

### Крок 1 - виберіть задачу

1. `Problem` -> `Problem(s) task flow` (`Ctrl+P`).
2. Додайте завдання та виберіть **Передача тепла**.
3. Підтвердьте за допомогою `OK`.

### Крок 2 - призначити матеріал

1. Виберіть сутність обсягу в дереві `Model`.
2. Відкрийте вкладку `Material` і призначте матеріал з усіма чотирма властивостями для конструкційної сталі:
   - **Теплопровідність** = `50` `W/(m*K)`
   - **Теплоємність** = `460` `J/(kg*K)`
   - **Щільність** = `7850` `kg/m^3`
   - **Коефіцієнт випромінювання** = `0`

Теплоємність і щільність не використовуються в стаціонарному розв’язуванні, але вони повинні бути присутніми, щоб об’єкт взагалі розв’язувався.

### Крок 3 - підтримуйте аналіз у стабільному стані

Відкрийте вкладку `Problem` і залиште **Увімкнути** непозначеним у груповому полі *Розв’язування в часі*. Потім розв’язувач збирає та розв’язує `K*T = f` один раз.

### Крок 4 - прописуємо хот-енд

1. Виберіть сутність поверхні на гарячому кінці.
2. Відкрийте вкладку `Boundary conditions` і відзначте **Температура**.
3. Встановіть значення `353.15` K, тобто 80 градусів Цельсія.

Пам’ятайте, що всі температури в Range FEA є абсолютними, у кельвінах.

### Крок 5 - остудіть решту

1. Виберіть поверхню, що покриває решта граней.
2. Відкрийте вкладку `Boundary conditions` і відзначте **Проста конвекція**.
3. Установіть **Коефіцієнт конвекції** = `10` `W/(m^2*K)` і **Температуру рідини** = `293.15` K.

Коефіцієнт приблизно `10` є репрезентативним для поверхні в нерухомому повітрі; примусове повітря ближче до `50`, а вода в сотнях або тисячах.

Це крок, який робить модель розв’язною. Без цього брусок має вхід тепла і не має виходу, і стаціонарний стан не існує.

### Крок 6 - розв'язати

1. `Solution` -> `Start solver` (`Ctrl+R`).
2. Засіб перевірки налаштувань повідомляє про відсутність матеріалів або граничних умов перед початком циклу.
3. Слідкуйте за прогресом у `Report` -> `Solver log file`.

### Крок 7 - перевірте результати

- вкладка `Results`: відображення **Температура**. Поле має плавно спадати від заданого гарячого кінця до температури рідини.
- Найхолодніша точка повинна залишатися вище температури рідини. Температура нижче `Tf` будь-де або вище встановленого `353.15` K означає, що щось подає енергію неправильним шляхом - перевірте знак будь-якого джерела тепла.
- **Тепловий потік** показує, куди рухається енергія, у `W/m^2`. Помножте значення на конвекційних гранях на їхню площу та порівняйте його з потужністю, що входить до смуги.
- **Коефіцієнт теплопередачі** має бути `10` на конвекційних поверхнях і `0` всюди. Це найшвидший спосіб підтвердити, що умова конвекції досягла елементів, які ви мали на увазі, і єдиний спосіб побачити, що обчислила корельована умова.
- точка моніторингу *температури* на холодному кінці дає відповідь у вигляді числа, а не кольору.

### Крок 8 - необов'язково, додайте джерело тепла

Щоб змоделювати нагрівач, вбудований у панель, виберіть сутність об’єму, відкрийте вкладку `Boundary conditions` і встановіть прапорець **Нагрівання**. Щоб доставити загальну кількість `P` ватів у смужку, введіть `P` — розв’язувач розподіляє його по об’єму об’єкта.

Використовуйте **Швидкість нагрівання (одиниця об’єму)** замість цього, якщо джерело розраховано на одиницю об’єму; введіть `P / V` `W/m^3`, щоб отримати ту саму суму - див. 1.4.

Стаціонарна температура повинна підвищуватися до тих пір, поки конвекційна поверхня не зможе скинути саме цю потужність - це перевірка енергетичного балансу в розділі 5.

### Крок 9 - необов'язковий, термічний стрес

Щоб перенести результат у структурний аналіз:

1. Додайте завдання **Аналіз напруги** *після* завдання нагрівання в потік розв’язування задач і надайте об’єкту структурні властивості, які йому потрібні.
2. Призначте умову навколишнього середовища **Температура** для структурного елемента з еталонною температурою без напруги, наприклад `293.15` K.

Розрахунок напруги збирає обчислені температури елементів і автоматично додає термін теплового розширення.

### Усунення несправностей

| Симптом | Причина |
|---|---|
| Розв'язати не сходиться | немає температурних умов і немає конвекційної поверхні, тому стаціонарний стан не визначено |
| *Об’єкту призначено матеріал, якому відсутні необхідні властивості* | відсутня одна з чотирьох обов'язкових властивостей - часто коефіцієнт випромінювання |
| Вся модель перебуває при одній температурі | тепло не надходить, або ніщо не відхиляє градієнт від заданого значення |
| Температура абсурдно висока | щільність у `W/m^3` була введена в умову *Теплота*, яка приймає загальну суму у ватах, або коефіцієнт конвекції занадто малий |
| Стінка між твердим тілом і рідиною не охолоджується | завдання нагрівання рідини виконується після завдання нагрівання, або група виконує одну ітерацію - поставте завдання нагрівання рідини першим і дозвольте групі виконати ітерацію |
| Рідина ігнорується теплом розв’язати | призначений - текучий матеріал вирішується тільки за допомогою *Теплопередачі в рідинах* |
| Температура всюди близько `293.15` K | сутність не було розкрито - перевірте журнал на відсутність матеріальної властивості |

## 4. Підручник - перехідний теплообмін

**Ціль.** Запустіть ту саму батончик при кімнатній температурі, увімкніть хот-енд і дізнайтеся, скільки часу потрібно, щоб розігрітися.

### Крок 1 - виберіть задачу

Те саме завдання **Передача тепла**, що й у підручнику 3. Якщо модель усе ще налаштована, потрібно додати лише параметри розв’язувача часу та початкову умову.

### Крок 2 - призначити матеріал

Ті самі чотири властивості. Тут мають значення **теплоємність** і **щільність**: разом із провідністю вони встановлюють коефіцієнт теплопровідності `k/(rho*c)`, який визначає швидкість руху фронту.

### Крок 3 - встановити початкову температуру

1. Виберіть сутність обсягу.
2. Відкрийте вкладку `Initial conditions` і відзначте **Температура**.
3. Встановіть значення `293.15` K.

Без цього модель усе ще починається зі стандартного `293.15` K, але його явне вказівка робить модель самодокументованою та дозволяє починати з будь-якого іншого стану.

### Крок 4 - налаштуйте розрахунок часу

Відкрийте вкладку `Problem` і в полі *Розв’язування в часі* встановіть:

| Поле | Значення |
|---|---|
| Увімкнути | галочкою |
| Наближення | `Backward difference (stable)` |
| Час початку | `0` |
| Розмір кроку в часі | `1` |
| Кількість часових кроків | `300` |
| Вихідна частота | `10` |

*Зворотна різниця* є неявним маршем - дивіться таблицю в 1.8 - і саме його слід використовувати тут. Він залишається стабільним на кроці часу, обраному для фізики, а не для сітки.

Виберіть часовий крок із постійної часу, яку ви очікуєте, маючи на меті приблизно п’ятдесят кроків над цікавою частиною кривої. Розділ 5 надає формулу для першої оцінки. Запис кожного десятого кроку зберігає розмір файлу результатів без втрати форми кривої.

### Крок 5 - зберегти граничні умови

Приписана **Температура** на гарячому кінці та **Проста конвекція** на решті поверхонь залишаються без змін. Кожен компонент — це таблиця залежно від часу, тож натомість для гарячої частини можна надати зміну: відкрийте редактор компонентів і додайте часові точки, щоб температура підвищувалася протягом перших кількох секунд, а не миттєво змінювалася.

### Крок 6 - додайте точку моніторингу

`Problem` -> `Define monitoring points`, помістіть точку на холодному кінці та встановіть для її змінної значення **Температура**. Криву розминки набагато легше читати як історію, ніж як послідовність кольорових картинок.

### Крок 7 - розв'язати

`Solution` -> `Start solver` (`Ctrl+R`). Журнал друкує один блок за крок часу:

```
time step:         1 of 300       | time =  0.000000e+00 [sec] | dt =  1.000000e+00 [sec]
```

, а потім ітерації розв’язувача матриці та статистика температури цього кроку.

### Крок 8 - перевірте результати

- Док `Model`, вкладка `Records`: один запис на записаний крок. Переходьте через них або анімуйте їх, щоб спостерігати, як тепловий фронт рухається в смужку.
- Вкладка `Results`: відображення **Температура**. Виправте діапазон відображення в записах так, щоб кольори означали те саме в кожному кадрі, інакше анімація сама масштабується, і прогрес буде непомітним.
- `Report` -> `Monitoring points` малює криву розігріву на холодному кінці. Зчитайте з нього постійну часу: час, щоб покрити приблизно 63 відсотки загального підйому.
- Останній запис має наближатися до результату стаціонарного стану підручника 3. Якщо це не так, цикл був занадто коротким.

### Усунення несправностей

| Симптом | Причина |
|---|---|
| Температура коливається і зростає від кроку до кроку | явний марш із занадто великим кроком у часі - перемкніть апроксимацію на *Зворотна різниця (стабільна)* або зменшіть `dt` |
| Результат майже не змінюється протягом усього циклу | крок за часом значно нижчий від постійної часу, або пробіг занадто короткий |
| Перший крок переходить до остаточної відповіді | крок у часі значно перевищує постійну часу, тому марш є фактично стаціонарним |
| Лише один запис був написаний | вихідна частота `0`, яка записує лише останній крок |
| Перехідний процес ніколи не досягає стійкого стану | це часто є правильним - перевіряйте стабільний режим, перш ніж підозрювати розв'язувач |

## 5. Перевірка моделі

Розв’язувач не має вбудованого набору перевірок, тому варто перевірити нову модель на те, що ви можете обчислити вручну, перш ніж довіряти їй. Чотири дешеві чеки в порядку корисності:

**Плоска стіна.** Для плити товщиною `L` і провідністю `k`, утримуваною на `T1` і `T2` на двох її сторонах, температура є лінійною поперек плити, а потік

```
q = k * ( T1 - T2 ) / L          [W/m^2]
```

Змоделюйте плиту за допомогою об’ємних елементів, напишіть обидві грані, переконайтеся, що середня площина розташована рівно посередині та що розрахований **Тепловий потік** відповідає `q`. Це вловлює неправильні одиниці, неправильну провідність і сітку, яка з’єднана не так, як ви думаєте. Уточніть сітку один раз і підтвердьте, що обидва числа залишаються на місці.

**Стіна з конвекцією.** Для тієї самої плити, що утримується на `T1` на одній стороні та охолоджується рідиною на `Tf` з коефіцієнтом `h` на іншій, охолоджена поверхня осідає на

```
Ts = ( (k/L)*T1 + h*Tf ) / ( k/L + h )
```

Порівняйте з обчисленою температурою поверхні. Це підтверджує умову конвекції, яка є частиною теплової моделі, в якій найлегше помилитися.

**Зосереджена постійна часу.** Для перевірки перехідного процесу візьміть тіло об’ємом `V` і площею поверхні `A` без заданої температури, починаючи з `T0` і охолоджене лише конвекцією. Хоча число Біо `h*V/(A*k)` залишається нижче приблизно `0.1`, тіло є майже ізотермічним і

```
tau  = rho * c * V / ( h * A )
T(t) = Tf + ( T0 - Tf ) * exp( -t / tau )
```

Зчитайте `tau` з історії точки моніторингу та порівняйте. Це одночасно підтверджує матрицю пропускної здатності, умову конвекції та ваш часовий крок, і це найшвидший спосіб вибрати часовий крок для реальної моделі, оскільки `tau/50` є хорошим першим припущенням.

**Енергетичний баланс.** Для стаціонарної моделі з відомою вхідною потужністю `P` конвекційна поверхня повинна скинути точно `P` при кінцевій температурі:

```
P = h * A * ( Ts_mean - Tf )
```

Зчитайте середню температуру поверхні зі статистики в журналі розв’язувача та перевірте баланс. Це єдина глобальна перевірка, яка виявляє значення тепла, введене як загальне, а не як щільність.

Для будь-якого з них уточніть сітку принаймні один раз і підтвердьте, що відповідь збігається, а не дрейфує.

## 6. Обмеження

### Обмеження моделювання

- **Лише лінійна провідність.** Провідність, ємність і густина елемента є константами під час розв’язання, зчитуються з таблиці матеріалів за температури попереднього циклу. Властивість, яка сильно залежить від температури, потребує ітераційної групи завдань для зближення.
- **Без зміни фази.** Немає прихованої теплоти та формулювання ентальпії, тому плавлення, твердіння, кипіння та конденсація не моделюються. Таблиця матеріалів не може представляти приховане плато.
- **Немає адвекції.** Енергія рухається шляхом провідності всередині тіла та шляхом конвекції через його кордон. Рухоме середовище не несе з собою енергії; використовуйте для цього *Теплопередачу в рідинах*.
- **Конвекція є граничною моделлю.** Корельовані форми використовують одну фіксовану кореляцію кожна - зовнішня плоска пластина для примусової течії, горизонтальні пластини для природної конвекції - з гідравлічним діаметром як характерною довжиною. Орієнтація поверхні, режим течії та внутрішній чи зовнішній потік не визначаються. Якщо коефіцієнт має значення, обчисліть його самостійно та введіть за допомогою *Простої конвекції*.
- **Коефіцієнт природної конвекції відстає.** Він оцінюється за температурою стінки попереднього розв’язання, тому однопрохідний стаціонарний прогін ефективно використовує початкову різницю температур.
- **Випромінювання лише через окремий тип задачі.** У самому тепловимірювачі немає терміну поверхневого випромінювання; Випромінювання корпусу потребує завдання *Радіаційна теплопередача*, його матриці кутових коефіцієнтів та ітерації між ними.
- **Поверхні є ізотермічними через свою товщину.** Поверхнева сутність проводить лише у власній площині. Змоделюйте стіну, градієнт наскрізної товщини якої має значення за допомогою об’ємних елементів.
- **Точкові елементи не проводять.** Точкова — це зосереджена ємність і джерело тепла, не більше того.
- **Стаціональна модель потребує виходу.** Без заданої температури та конвекційної поверхні матриця є сингулярною, і розв’язок не сходиться.
